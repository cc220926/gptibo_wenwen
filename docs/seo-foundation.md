## 实现

- 新入口 `worker/storefront-entry.ts` 将所有 `/api/` 请求以原 Request 和 Env 直接转给原处理器，返回原 Response；scheduled 直接引用原函数。成功的后台商品设置写入只额外清除本机 SEO 缓存，缓存异常不会改变原响应。未读取、克隆或改写回调正文。
- 仅精确配置的主站来源启用 SEO。配置缺失、格式不合法或来源不一致时保持原站行为，分站、自定义域名和推广路径不会自动获得收录权限。
- 公共 HTML 通过既有主站 `/api/catalog` 处理逻辑读取零售价、商品形象、可售状态、隐藏及下架信息。使用只允许单条 SELECT、禁止 run 和 batch 的数据库适配器，不传入 Cookie、访客参数或分站身份；不调用支付、供货或邮件服务。
- 公共目录使用独立 `SEO_CATALOG_LIMITER`，不借用买家 API 配额。配置为每个 Cloudflare location 约 6 次刷新/60 秒；同一主站共用一个 key，不随 URL、查询参数或访客 IP 改变。该限流是 Cloudflare 的近似、分地区预算，不是全球严格上限。绑定缺失、拒绝或出错时不开始数据库读取，应用仍回退可用。
- 目录有 15 秒内存缓存和并发合并。请求超过 1.5 秒回退后，未完成的数据库操作仍保持合并状态，直到真正结束；失败后退避 5 秒。后台商品设置写入清除所在实例的缓存，其他实例最多保留短 TTL；下单始终由原接口核价。
- 只有本次刚读取的新鲜主站目录会提供一次性初始数据，显式白名单保留前端需要的价格、须知、质保、优惠、支付费率、品牌、客服和公告；不复制未知字段、采购成本、订单或凭据。JSON 转义避免闭合 script。客户端校验来源、结构与 5 秒时限后消费一次；缓存快照、过期或异常数据、分站、后续轮询均继续走原目录 API，避免用旧缓存启用购买。
- 首页和有效商品页在原 React 挂载点注入独立文字、规格表及导航，JavaScript 加载后再替换为原展示和交易界面。这张表格也会在正常用户的首次绘制中出现，慢脚本或脚本失败会延长显示；不能将它仅描述成未启用 JavaScript 时的备用界面。这是已确认并触发生产回退的首屏缺陷。
- 指南目录和五篇文章先于目录读取处理，无须数据库或限流服务即可返回正文和订单入口。品牌可使用已有缓存，否则使用安全默认值。
- 独立生成 robots 和 XML sitemap；仅包含首页、当前公开商品、指南目录和五篇文章。按目录数据动态生成，不把隐藏商品、未知商品、订单、后台、API 或分站放入地图。不存在的内容页返回真实 noindex 404。
- 首页、商品页和指南页提供标题、描述、canonical；查询参数不进入规范网址。规范化首页别名及结尾斜线，保留跳转请求的普通查询参数。
- SPA 进入订单页移除 canonical 并设置 noindex；从直接访问的订单页返回公开页面也能恢复元信息。订单 HTML 只增加来源标记，仍为空的私有应用壳，不注入任何订单数据。
- 全局静态文件的 noindex 和安全头仍保留。公开响应单独设置安全头与收录头；公开内容用 no-store，避免跨身份缓存。HEAD 无正文。
- 公共目录读取超过 1.5 秒时不等待 SEO 完成，公开应用回退到原页面并保持 noindex；sitemap 故障返回可重试的 503，不冒充有效 XML。这个时限不取消已经开始的 D1 只读操作。
- 通用 robots 允许搜索爬虫访问公开内容，继续禁止私有路径；GPTBot 单独禁止抓取。搜索抓取与训练许可分开处理。没有专用 AI 文件、虚构评价、评分或“保证被推荐”的标记。

## 启用与回退

本分支代码和示例配置中的 `STOREFRONT_SEO_ORIGIN` 默认为空，SEO 默认关闭。忽略的生产配置未修改，源文件中的中性 noindex 页面和 robots 仍为安全默认值。

未来经部署流程使用时，需要在同一次版本中检查四项配置：

- `main` 指向 `worker/storefront-entry.ts`。
- `assets.run_worker_first` 为 `true`，否则根页面或导航可能被静态 SPA 回退绕过。保持原 ASSETS 绑定、资源、cron、密钥及所有业务开关。
- 新增独立 `SEO_CATALOG_LIMITER` 绑定，namespace 必须与买家限流区分；保留现有三个业务 limiter，不改它们的预算。
- `STOREFRONT_SEO_ORIGIN` 设置为经核实的主站 HTTPS 来源，只含协议和主机。只有本机验收允许 loopback HTTP。不得填后台域名、分站域名或生产凭据。

关闭该来源配置会恢复默认禁止收录行为，不能代替需要时的整个版本回退。尚未上线，本轮不创建发布标签。

2026-11-21 隔离演练确认，直接退到纯旧版本会缺少候选 JS/CSS；正式发布前必须先准备保留两版静态资源的兼容回退版本。该版本保持旧业务代码与 HTML，但属于新部署，不能把原生产版本 ID 当成已经兼容。实际红／绿证据、交易恢复范围和未验证项见 [隔离预发布与回退演练](./seo-preproduction-rehearsal.md)。演练未改变生产配置或部署。
