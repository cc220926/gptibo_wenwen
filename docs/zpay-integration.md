# ZPAY 自营库存商品接入状态

目前只准备了协议层代码，**未接入订单路由、未配置商户凭据、未开放收款**。现有 ChatGPT 上游代收链路保持不变。

## 已核对的接口

- 用户给的 `node.zip` 只有 `node/pay.txt`，展示了 MD5 排序签名和页面跳转支付；它没有回调、订单反查、关单或退款实现。示例中的 URL 拼接也没有编码参数，不能直接复制到生产环境。
- [ZPAY 官方文档](https://api.z-pay.cn/doc.html)支持 `submit.php` 页面跳转和 `mapi.php` API 下单，支付通知采用 MD5 签名；文档要求校验通知签名、订单金额，并建议反查订单。当前协议代码使用官方 `https://zpayz.cn/submit.php`，只生成支付宝付款链接。
- 本站自营订单号形如 `YMX-` 加 32 位十六进制字符。ZPAY 商户订单号最多 32 位，协议代码只传后 32 位，并在回调中恢复原订单号。
- `worker/payments/zpay-protocol.ts` 生成 URL 编码后的签名链接、拒绝重复回调参数，并反查商户号、订单号、支付方式、金额和支付流水。签名回调本身不能触发交付，必须再使用 ZPAY 订单查询确认。

## 正式启用前的阻塞项

1. 支付宝渠道仍在审核中。按[商户接入协议](https://api.z-pay.cn/news?id=8)的“不接入发卡平台”条款，需取得 ZPAY 对拟售自有库存兑换码的明确接入答复。商品类别获准前，不配置生产商户密钥或开放入口。
2. 官方公开文档未列出关单、退款结果查询或退款请求幂等参数。现有支付服务依赖这些能力来安全释放库存、确认售后和避免重复退款。需向 ZPAY 取得接口说明，或设计经人工核验的退款流程及逾期付款处理流程后再接入订单路由。
3. 审核通过后把商户 ID、密钥及可用渠道写入 Worker Secret；不得写入源码或聊天。使用小额真实订单，验证支付、重复回调、延迟到账、超时、交付、退款与对账，再单独打开自营商品收款开关。
