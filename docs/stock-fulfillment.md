# 自有商品、卡密库存与服务交付

本功能运行于 **Cloudflare Workers + D1**。Go + PostgreSQL 后端尚未接入本模块，不能将本文迁移应用到 PostgreSQL。既有充值、接码展示、X 赠送和供应商采购保留原来的处理器，不会自动切换为自有库存。

## 开启

1. 备份正式 D1 数据库，按 README 应用全部迁移。`0053_generic_fulfillment.sql` 增加商品、库存和交付任务表，已有规格的 `delivery_type` 默认为 `legacy`。
2. 在安全位置创建并备份独立的 32 字节密钥。例如在仓库根目录执行以下命令，已有密钥时不要重新生成：

   ```sh
   mkdir -p .secrets
   # 仅在首次初始化时执行，避免覆盖已有密钥：
   (umask 077; set -C; openssl rand -base64 32 > .secrets/cdk-encryption-key)
   npx wrangler secret put CDK_ENCRYPTION_KEY -c wrangler.production.jsonc < .secrets/cdk-encryption-key
   ```

   密钥应与数据库备份分开保存。已导入库存后，直接更换密钥会停止解密、导入与新购买，须恢复原密钥；当前不提供在线密钥轮换。不要把密钥或真实库存提交到 Git。
3. 配置支付渠道、支付回调和 Resend 邮件参数，设置可信的 `MAIL_PUBLIC_ORIGIN`，保留每分钟的定时任务。如使用 ZPAY，请先按 [ZPAY 接入说明](zpay-integration.md)重置密钥、设置 Secret 并完成实付验收。
4. 在目标 Worker 设置 `SERVICE_CHECKOUT_ENABLED=true`，同时保持 `ORDER_TESTING_ENABLED=false`。默认使用现有直连支付宝；设置 `SERVICE_PAYMENT_PROVIDER=zpay` 后，自有库存、人工交付规格及已开放的 Muse 规格可用 ZPAY。本开关独立于 `EMAIL_PRODUCTS_ENABLED`。配置不全时暂停新购买，已确认的订单及库存不会被删除。
5. 构建并部署后，在管理后台「自有商品与库存」新建商品和规格。先保持规格暂停，导入库存并检查说明、售价和成本，再开放新购买。

## 后台操作

- **商品**：名称、分类、介绍。分类直接输入新名称，也可选择已有名称。分类不决定交付方式。
- **商品上下架**：在「自有商品与库存」的商品卡片点击「下架并隐藏」，前台目录和直达详情页不再展示其所有规格，也不能创建新订单；「恢复展示」可重新开放展示。已有订单、库存和规格设置保留。「开放新购买」仅控制单个规格的可购买状态，不负责隐藏商品。
- **规格**：独立售价、购买说明、交付说明和交付方式。支持「自有库存自动交付」和「人工服务交付」。已有规格的交付方式和所属商品不可变，需要切换时新建规格。
- **库存**：选择规格后「管理库存」，一行一条，单次最多 100 条，每条最多 8192 字。CDK、单行账号资料和 HTTPS 领取链接均可作为交付内容。导入前检查整批重复；发现已导入内容时整批拒绝。采购成本按本批每条记录，用于原订单清账。
- **停用**：只能停用未分配库存；不删除已售记录、不释放已交付内容。
- **人工交付**：从后台「人工交付」工作台查找已付款订单，可按状态、订单号或下单邮箱筛选，默认按下单时间优先处理较早订单。打开详情后先填写内部处理说明并点击「开始处理」，或直接填写客户可见的交付结果并确认交付。未付款、退款中、已退款和已禁止兑换的订单不能交付。
- **通知**：客户可在原订单领取；邮件独立重试，不影响已交付状态。后台订单详情显示邮件受理状态，可重试原邮件。「邮件服务已受理」不表示已经送达收件箱。

当前每单购买一份，新增自有商品仅支持平台直营；代理销售不开放。现有代理商品继续使用原流程。

### 上架一个人工交付商品

1. 在「自有商品与库存」新建商品，填写商品名称、分类和介绍。
2. 添加规格，交付方式选择「人工交付」，设置售价、购买说明和交付说明，并勾选「开放新购买」。购买说明中写清服务范围、联系客服交付的方式以及客户需要配合的事项；不承诺交付时间时无需填写预计时效；无需导入库存。
3. 客户在商城购买并完成付款后，需点击订单中的「联系客服」，提供订单号，由客服线下人工交付；已付款待交付订单会直接展示商店现有客服联系方式。付款不会自动发货。订单同时进入后台「人工交付」工作台，供客服核对与记录。待处理队列只包含可继续交付的人工订单，Muse 自动采购订单独立处理；售后中、已有退款或禁止兑换的待交付订单归入「已暂停交付」，迟到付款等异常归入「需人工核对」。
4. 在订单中开始处理，客户可看到「人工处理中」。处理完成后填写客户可见的交付内容或结果，以及单独的内部处理说明，点击「确认交付并通知客户」。内部说明仅保存在后台处理记录中。
5. 实际商品通过客服人工交付。若客服另在后台提交了交付结果，客户也可在原订单查看和复制，邮件通知独立发送；前台不承诺系统自动发货。重复确认或重复支付回调不会覆盖已有结果，也不会重复创建交付。

人工交付与自动库存使用相同的加密配置、付款验签和订单权限校验，支持直连支付宝及 ZPAY；付款确认只进入人工队列，不会自动将订单标为已交付。本次扩展使用已有数据库表，无需新增迁移；已有安装仍应确保已应用全部现有迁移。

## ChatGPT Plus 成品号展示

名称含 ChatGPT 和「成品号」或「成品账号」的自有商品使用浅紫玻璃质感的单张立体卡片，目录与详情共用同一视觉，并提供 `/product/gpt-plus` 入口。展示使用数据库商品介绍、规格、价格与购买说明；交付方式仍由规格独立设置，卡片样式不改变履约方式。卡片与阴影以 6.5 秒周期轻微上下浮动；减少动态效果设置下停止动画。卡面 1M 表示一个月，不使用未经配置确认的地区标识。

## 一笔订单如何执行

创建订单时，事务同时保存商品名称、规格、购买说明、交付说明及交付方式快照，并预留该规格的一条库存。库存由数据库在事务内选择，不能被两笔订单同时占用。重试创建订单使用原请求编号。

预留时间为 15 分钟。没有支付交易，或支付渠道已经确认交易关闭，才能在到期后释放库存；支付结果未知时继续保留。后台核对支付后，定时任务会继续清理。若释放后收到迟到的成功收款通知，原订单进入人工核对，不会挪用其他客户库存或自动重新收款。

经过现有支付渠道验签、金额和订单核对后，系统将原库存绑定为已交付，同时更新订单与处理记录。客户不必等邮件成功即可在原订单领取。人工服务则进入待处理任务，工作人员提交结果后完成交付。

邮件正文、发件人和收件人在首次发送前冻结并加密保存。后续重试复用同一正文及幂等键；首次尝试满 23 小时仍未确认时停止自动重发，显示待人工核查。请到邮件服务商核查原消息，勿换编号盲目重发。

卡密使用 AES-GCM 加密，附加认证数据绑定库存编号；去重使用独立用途的 HMAC。库存列表、后台订单列表和处理记录不返回卡密原文。只有通过原订单权限校验的客户及授权管理员订单详情可读取。退款后原库存隔离，不自动重新出售。

## 扩展其他服务

`fulfillment_tasks` 保存每个订单的独立交付任务；`worker/fulfillment/service.ts` 处理预留、交付与通知，`worker/fulfillment/admin.ts` 提供后台操作。商品描述与前台页面读取数据库，不需要为每种 CDK 增加页面代码。

以后新增同类 CDK 或人工服务，直接配置商品和规格。不同协议的接码、充值或开通服务仍需要供应商适配器及对应的交互与结果核验；本模块不会把新业务自动当成「发送一条字符串就完成」。添加新的交付方式时，应保留订单快照、原任务编号、付款及退款校验，并加入重复执行、超时、迟到结果和客户隔离测试。

## 验证

`tests/generic-fulfillment.test.ts` 使用内存数据库和模拟支付／邮件，覆盖重复导入、库存并发竞争、重复付款回调、事务回滚、迟到付款、客户隔离、邮件幂等重试、人工交付、ZPAY 人工收款、工作台权限／筛选／分页、暂停保护和历史快照。

这些测试不向真实支付或邮件服务发送请求，不能替代目标部署环境的实际支付回调与邮件投递验收。
