# 码支付 V1 接入（Workers）

依据用户提供平台的公开文档：https://mzf.mapay.cn/doc/epay_mapi 。实际请求前缀为 `https://mzf.mapay.cn/xpay/epay/`，不是 ZPAY 的路径。仅接支付宝；尚未接微信、V2 RSA、自动退款或关单。

- 商户身份使用独立 `MAPAY_PID` / `MAPAY_KEY` 服务端 Secret，不复用 ZPAY 凭据，不把 KEY 写到源码、浏览器、命令行参数或日志。
- `MUSE_PAYMENT_PROVIDER=mapay` 只选择新 Muse 订单；通用自营商品默认仍由 `SERVICE_PAYMENT_PROVIDER` 控制。支付行冻结原 provider/account，切换默认值不改历史订单。
- 按文档原始字段排序 MD5，通过服务端 `POST /xpay/epay/mapi.php` 准备同一商户订单。核对返回金额，再独立查单核对商户、订单、金额和交易号；拒绝重定向、超限响应和非许可付款地址。
- 返回支付宝官方实际付款地址时，商城只把该地址生成为付款码。若平台仅提供同站收银台网页，则只显示「前往支付」按钮，不把网页入口伪装为付款码。旧签名收银台链接也保持按钮显示。实测 API 可同时返回 qrcode 与 urlscheme；仅采用经验证的二维码地址，不自动执行附带的唤起协议。平台返回不支持的链接时停止收款入口，不盲目跳转。
- 当前支付宝通道实测收银台有效期为五分钟；从准备请求开始保守限制本地期限为五分钟，且不延长原库存预留。API文档未提供统一有效期字段，通道超时配置变化后需重新核验。点击「已付款，核对结果」收起付款入口，返回页面后自动查询原订单；点击按钮和跳转本身均不记为到账。
- 回调路径 `/api/payments/notify/mapay`，支持 GET 和 URL 编码表单 POST；拒绝重复参数、混合 URL/表单来源、超限或伪造签名。
- 签名正确仅是候选。服务端再查询原商户订单，交叉核对商户、订单、支付宝方式、金额、已付款状态及支付流水，全部一致后原子记账并启动原商品履约。return_url 跳转不作为付款凭证。
- 查单禁止重定向，有超时及实际流字节上限；不把网关响应、KEY、收银台链接、客户资料记入错误日志。
- 回调诊断仅记录固定白名单的 provider、outcome、stage、reason。`received` 表示已进入回调处理函数（全局限流之后），`applied` 表示核验和记账处理成功；`notified_at` 只记录成功处理时间，为空不代表没有收到请求。`gateway_not_confirmed` 表示原单查询状态或交易号未通过交叉核验，不能据此断言付款人没有扣款。请求参数、签名、订单号、凭据及原始错误均不写入这些日志。
- 没有已核实的交易关闭接口，本地付款入口超时两分钟宽限后关闭；网关旧链接仍可能支付。最近 30 天本地关闭单继续反查，晚到账进入原订单人工核对，不分配新的库存或重复采购。文档未明确的“订单不存在”返回不视为已安全关闭。
- 没有已核实的幂等退款/退款查账接口。管理员先在码支付商户侧完成真实退款并核对金额，再在本站输入真实退款流水登记；本站不会自动再次转账。

## 配置与验收

私密配置只保存在被忽略文件或 Secret 中。通过标准输入写入 Cloudflare Secret；不要把 KEY 放进终端命令参数或聊天。首次启用需要足够供货余额、真实可交付商品、实际支付/交付及退款验收。普通商户查询 code=1/active=1 只能证明身份可用，不能证明支付宝通道和真实回调已经验收。

生产的 Muse 本次保持暂停，不创建真实采购。变更商品使用版本核对，保存修改前商品快照；历史采购意图不重写。未完成实付验收前不得将本适配描述为全链路已验收。

## 已扣款但订单未确认的排查

先核对同一笔订单，不要求买家重复付款。依次核对实际支付宝账单、码支付订单详情的支付时间和第三方流水、平台回调日志、本站回调诊断及主动查单。平台自身仍待支付或超时时，本站返回失败可能是付款核验尚未通过，不能通过跳过查单或手工制造成功回调来修复。

当前云端通道提供静态收款码，付款人与订单的关联依赖平台识别收款后匹配。通道显示在线、创建订单成功、二维码可扫描、回调地址可访问，以及单元测试通过，都不能单独证明实际收款匹配正常。还应核对通道实际登录账户与收款码所属账户一致、平台应付金额与实付金额一致、实际付款时间位于原订单窗口，并确认平台捕获了对应支付宝流水。若平台缺少收款记录，需要恢复其云端识别或由平台查明漏单；商城代码无法自行证明该笔资金到账。
